## 光栅图形管道

#### 理解如何绘制光栅图元
最简单的`光栅图元(primitive)`就是一个顶点。  

光线成像的原理，视口和视锥体结构完全相同(见”理解视角“)。  
在已知图元顶点位置的情况下，连线的视口点反而是未知的。这与光线追踪相反。该缩放公式为`y=zy'/z'`。  
视口上的图元关联集会被光栅化绘制为像素(分解fragments)。我们可以保留两对顶点的任意信息以后进行某种用途的插值。  

`▼`其他技术均是此原理的附加品而已。建议读者始终记忆这一点。  
`▼`该过程会被openGL实现为矩阵运算。不建议读者去死扣其"投影"矩阵的"魔法"。从结果来看这一大堆推导只做了一件简单的事情。

#### 如何看待图形管道
`▼`出于生产目的，则图形管道各种功能会很重要。若注重图形学理论，则应该视为仅可选的渐进式学习过程。这一部分非常复杂杂乱。主要复杂度也在很多性能优化技术。  

#### 步骤
图元顶点会传给`着色器(shader)`，着色器机制输出片。程序员必须自己开发所有着色器。  
一旦产生2D的片像素。最后一个阶段是**混合(blend)**，Z-buffer用于处理这些片的遮挡并完成图像。对象之间并不知道彼此的上下文是该算法的主要特点。  

#### 纹理映射
设计`纹理映射(texture mapping)`机制可以对某处表面进行`纹理查找(texture lookup)`。纹理坐标最常见的绑定方法是作为原图的某种顶点属性。  
一旦将图像映射到表面的机制存在，就有许多不那么明显的方法可以使用它，超出了引入表面细节的基本目的。纹理可用于附加着色计算细节、制作阴影、影响照明，甚至定义表面形状，在复杂的交互程序中，纹理甚至被用来存储各种与图片无关的数据。

### 架构知晓
本文可能需要随时进行调整。总之目前理解如下，我不是驱动方面的工程师。

```ruby
    C++程序     => 驱动程序  => GPU
openGL, 窗口库
 
  主机进程内存     系统驱动内存   显存
```
openGL是一组标准，本文特指你正在使用的特定实现版本库。  
编程时，需要知道openGL、窗口库、驱动都是独立实现于语言和硬件平台的，并且职责分离。  

窗口库直接与驱动直接对话，还处理操作系统方面的输入输出(同样特定实现)。以便将显存中的图像读取至实时窗口中。   

### 数据缓冲器
```cpp
void glGenBuffers(n, *bufferIDs);
```
向驱动申请预留一个合法的缓冲器(未创建)可用ID。  

```cpp
void glBindBuffer(ENUM, bufferID);
GL_ARRAY_BUFFER
GL_ELEMENT_ARRAY_BUFFER
```
在驱动中创建类型`缓冲器`。另外，之后的某些访问将默认针对此缓冲器进行操作。  

这称为openGL API的**状态机（State Machine）**设计，特征之一是程序记住了某些设置，函数会自动使用这些设置。  
**GL_ARRAY_BUFFER**就是一种状态，记录了当前使用的该类型的缓冲器实例。  
这两个值可以独立使用，但都只能**绑定**一个。  

```cpp
void glBufferData(ENUM, sizeof(data), *data, ENUM2);
GL_ARRAY_BUFFER GL_ELEMENT_ARRAY_BUFFER
GL_STATIC_DRAW  GL_STREAM_DRAW GL_DYNAMIC_DRAW
```
向当前绑定的类型缓冲器发送数据。  
最后一个参数是优化选项，指示硬件某种优化。  

### 顶点解析对象
```cpp
void glGenVertexArrays(n, *ids);
void glBindVertexArray(id);

void glVertexAttribPointer(att_index, unit_size, unit_type(ENUM), normalized(ENUM), stride, (void*)0);
                          // 属性序号   数据个数    每个数据类型                      顶点间隔   当前偏移(点内开头)
void glEnableVertexAttribArray(att_index);
```
申请以及绑定`VAO对象`。  
该抽象对象是为了记下某个缓冲器中的状态，尤其是其数据格式如何解释。先绑定它，再绑定缓冲器，再定义顶点格式。  
最后，启用此序号的属性。  

另外一种缓冲器GL_ELEMENT_ARRAY_BUFFER状态会被当前VAO直接隐式绑定。  
它们用于存储顶点索引数据(为了在绘制时，重复使用顶点)。因此依次访问索引，而不是顺序顶点。  
在设置VAO时一起完成它。  

绘图命令直接使用当前绑定VAO作为数据来源绘制图元。

### 着色器
顶点首先被交付给顶点着色器。着色器之间仅通过输入in输出out关键词变量连接，而layout和location关键字用于读取第一阶段的顶点属性以及指定片段阶段的输出的颜色缓冲器。  
着色器使用专用语言。  
```cpp
#version 330 core

layout(location=0) in vec3 aPos;         // 读取顶点0号属性
void main() { gl_Position = }            // 顶点阶段必须输出该预定义值

layout(location=0) out vec4 FragColor;   // 片的输出
                                         // 指定输出到其他序号颜色缓冲器(如果存在)

in type var   // 传递
out type var
uniform type uTime;
```
```cpp
int glGetUniformLocation(program, "u_name");   // 寻找着色器程序uniform变量位置(通过名称键)
glUniform4f(location, value)                   // 设置值
glUniformMatrix4fv(location, count, transpose(ENUM), data)
// GL_FALSE
```
需要在激活着色器之后。
